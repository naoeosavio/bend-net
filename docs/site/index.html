bend-net

HTTP and WebSocket, written in Bend

HTTP/1.1, HTTP/2, ws:// and wss:// in user-land Bend, on top of the TCP.* kit, with package-local DNS and TLS (client and server, OpenSSL through dlopen — no link flags). The native code is the byte-level socket effects, the A-record resolver and the TLS effects; everything else is Bend.

Install

curl -fsSL https://bend-lang.com/install.sh | sh   # Bend 2.0.21+
git clone https://github.com/naoeosavio/bend-net

Local import, relative to your file (always run from the repo root, so the imports resolve):

import Base
import ./lib/httpx.bend as HTTPX

def main() -> IO(Unit):
  do IO<Unit>:
    body : String <- HTTPX.fetch("https://example.com/")
    IO.print(body)

Or through the hub, after a publish — imports are not transitive, so import the API from its own file:

import 0x<hash>/httpx.bend as HTTPX

What is in the box

  • HTTP/1.1

    Pure request/response codec plus a keep-alive server and client lane: Content-Length and Transfer-Encoding: chunked in both directions, plaintext (http://) and over TLS.

  • HTTP/2

    A full codec in lib/http2.bend and a mini-H2 inside lib/httpx.bend: framing, HPACK (static table, Huffman and dynamic-table decode), flow control with WINDOW_UPDATE credit, CONTINUATION reassembly.

  • WebSocket

    One RFC 6455 implementation in lib/wsm.bend for both ws:// and wss://: handshake, masking, fragmentation, ping/pong, close codes.

  • DNS and TLS

    A package-local A-record resolver (fail-closed host checks) and a client + server TLS lane with ALPN h2, certificate chain and hostname verification (SSL_set1_host).

  • Fail-closed

    Every parser answers Result with a stable code: 400/413/502/503 (codec), 601-605 (DNS), 611-616 (TLS). A truncated body is never read as a whole one.

  • Bytes stay bytes

    Frames never go through UTF-8: the byte effects send and receive List<&2, U32>, so a binary WebSocket frame or a chunked body survives the round trip untouched.

API

The three modules share one shape: a request is method & path & headers & body, a response is status & headers & body, and headers are List<&1, String & String>.

lib/httpx.bend — server

EntryShape
server.on / server.on_alpn Sequential generic server; the ALPN split feeds h2 and HTTP/1.1 into one handler
server.concurrent / _alpn Interleaved streams, answered in any completion order
server.stream / _alpn / _plain Upload streaming: a pure handler classifies SrvReqHead / SrvReqData into Continue, RespondEarly or Cancel
server.on_h1_plain / server.on_h1 Keep-alive HTTP/1.1 over plain TCP / over TLS
server.once / server.once_h1 One connection, then stop — the entry a test wants

lib/httpx.bend — client

EntryShape
client.once / _insecure Dial, one exchange, close; dispatches both ALPN answers
client.on / client.connect One dial, N sequential requests, sid and HPACK table threaded through the state
client.concurrent Pipelined N requests drained through slots
client.stream / _plain Download streaming to a pure handler (StreamHead / StreamData)
fetch / fetch_bytes / request URL and text conveniences over client.once

lib/wsm.bend — WebSocket

EntryShape
server_on / server_on_plain Event loop with one ~H: Ev -> IO(WSOut) for handshake, messages, ping/pong and close
client_on / client_on_plain The client mirror of the same event API
client_echo / client_echo_plain One-shot echo convenience
show_masked / frame_need / frame_split Pure codec: masking, length prefix, incremental split into Got / NeedMore / Bad

Two delivery modes

Every HTTPX entry belongs to exactly one discipline, and the handler signature tells which:

  • Whole response — ~H: Request -> IO(Response). IO is allowed (DB, upstream, files), the handler sees the complete request.
  • Streaming — ~H: SrvEv -> SrvOut. A pure classifier: per event it answers Continue, RespondEarly or Cancel, and every byte of IO stays in the loop. That buys O(1) per chunk and early answers without draining — and it means a streaming handler cannot touch a file or a database.

Rule of thumb: need IO while deciding? Use server.concurrent / server.on / client.once. Need incremental delivery? Use server.stream / client.stream.

Tests

The suite is golden-based: each file prints a score and the gate compares it with the #|N marker at the end. A few entries:

bend tests/io/httpx_h1_pure.bend          # 481441153
bend tests/io/httpx_h1_sec.bend           # 15
bend tests/io/httpx_plain_h1.bend         # 4
bend tests/io/httpx_site.bend             # 3
bend tests/io/wsm_handshake_sub.bend      # 12
bend tests/io/hpack_huffman.bend          # 11111111

check.sh runs two gates: --checks typechecks the library and the examples, --tests runs the suite. --changed narrows both to what an edit can break.

Security policy

  • Every renderer rejects CRLF and NUL in a name or a value with Fail 400: header injection ends closed, never as extra fields.
  • Heads are capped at 16 KB, bodies at the lane's own fuel; an oversize message is 413.
  • Client WebSocket frames are masked with a key from the host entropy pool.
  • Name hosts resolve through the package resolver; the resolved IP is transport-only, so Host keeps the original name.
  • TLS verifies the chain and the hostname; there is no custom-CA or SNI override, only *_insecure for loopback.
