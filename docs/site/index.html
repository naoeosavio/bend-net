bend-net

HTTP and WebSocket, written in Bend

HTTP/1.1, HTTP/2, ws:// and wss:// are user-land Bend code on the TCP.* kit, with package-local DNS and TLS for the client and the server. The native code holds the byte-level socket effects, the A-record resolver and the TLS effects. Each effect has a C twin for the binary target and a JS twin for every other lane. The C twin uses OpenSSL through dlopen, with no link flags. The five TLS JS twins share one portable runtime, TLS 1.2 + 1.3 in pure JS over the host's crypto. All the other code is Bend.

Install

curl -fsSL https://bend-lang.com/install.sh | sh   # Bend 2.0.21+
git clone https://github.com/naoeosavio/bend-net

A local import is relative to your file. Always run the code from the repo root, so the imports resolve:

import Base
import ./lib/httpx.bend as HTTPX

def main() -> IO(Unit):
  do IO<Unit>:
    body : String <- HTTPX.fetch("https://example.com/")
    IO.print(body)

Or use the hub, after a publish. Imports are not transitive, so import the API from its own file:

import 0x<hash>/httpx.bend as HTTPX

What is in the box

  • HTTP/1.1

    The HTTP/1.1 code is a pure request/response codec with a keep-alive server lane and a keep-alive client lane. It uses Content-Length and Transfer-Encoding: chunked in both directions, for plaintext (http://) and for TLS.

  • HTTP/2

    lib/http2.bend holds a full codec and lib/httpx.bend holds a mini-H2. Both codecs read and write frames, and both do HPACK (static table, Huffman and dynamic-table decode). They also do flow control with WINDOW_UPDATE credit, and CONTINUATION reassembly.

  • WebSocket

    lib/wsm.bend holds one RFC 6455 implementation for ws:// and wss://. It covers the handshake, the frame mask, fragmentation, ping/pong and close codes.

  • DNS and TLS

    A package-local A-record resolver fails closed on the host checks. One TLS lane serves the client and the server, with ALPN h2 — one contract, two wire implementations. The binary target uses OpenSSL through dlopen, and every other lane uses TLS 1.2 + 1.3 in pure JS. Both implementations verify the certificate chain and the hostname. The dial is Base's TCP.connect, and the effect does only the handshake.

  • Fail-closed

    Every parser answers Result with a stable fail code. The codes are 400/413/502/503 (codec), 601-605 (DNS) and 611-616 (TLS). No parser reads a truncated body as a whole one.

  • Bytes stay bytes

    Frames never go through UTF-8: the byte effects send and receive List<&2, U32>. Thus a binary WebSocket frame or a chunked body stays untouched in the round trip.

API

The three modules share one shape. A request is method & path & headers & body, and a response is status & headers & body. Headers are List<&1, String & String>.

lib/httpx.bend — server

EntryShape
server.on / server.on_alpn Sequential generic server; the ALPN split feeds h2 and HTTP/1.1 into one handler
server.concurrent / _alpn Interleaved streams, answered in any completion order
server.stream / _alpn / _plain Streamed upload: a pure handler classifies SrvReqHead / SrvReqData into Continue, RespondEarly or Cancel
server.on_h1_plain / server.on_h1 Keep-alive HTTP/1.1 over plain TCP / over TLS
server.once / server.once_h1 One connection, then stop — the entry a test wants

lib/httpx.bend — client

EntryShape
client.once / _insecure Dial, one exchange, close; dispatches both ALPN answers
client.on / client.connect One dial, N sequential requests, sid and HPACK table threaded through the state
client.concurrent Pipelined N requests drained through slots
client.stream / _plain Streamed download to a pure handler (StreamHead / StreamData)
fetch / fetch_bytes / request URL and text conveniences over client.once

lib/wsm.bend — WebSocket

EntryShape
server_on / server_on_plain Event loop with one ~H: Ev -> IO(WSOut) for handshake, messages, ping/pong and close
client_on / client_on_plain The client mirror of the same event API
client_echo / client_echo_plain One-shot echo convenience
show_masked / frame_need / frame_split Pure codec: the frame mask, length prefix, incremental split into Got / NeedMore / Bad

Two delivery modes

Every HTTPX entry belongs to exactly one discipline. The handler signature tells which discipline:

  • Whole response — ~H: Request -> IO(Response). The handler can use IO (DB, upstream, files), and the handler sees the complete request.
  • Streaming — ~H: SrvEv -> SrvOut. A pure classifier answers Continue, RespondEarly or Cancel for each event, and every byte of IO stays in the loop. This design gives O(1) for each chunk and early answers without a drain. Thus a handler in this mode cannot touch a file or a database.

Rule of thumb: if you need IO while you decide, use server.concurrent / server.on / client.once. If you need incremental delivery, use server.stream / client.stream.

bend tests/io/hpack_huffman.bend          # 11111111

check.sh runs two gates. --checks typechecks the library and the examples, and --tests runs the suite. --changed narrows both gates to what an edit can break.

Security policy

  • Every renderer rejects CRLF and NUL in a name or a value with Fail 400. Header injection ends closed, never as extra fields.
  • A head has a cap of 16 KB. A body has a cap of the lane's own fuel. An oversize message is 413.
  • The client masks WebSocket frames with a key from the host entropy pool.
  • A name host resolves with the package resolver. The resolved IP is transport-only, so Host keeps the original name.
  • TLS verifies the chain and the hostname against the root store that the host ships. The code has no custom-CA override and no SNI override, only *_insecure for loopback.
