RFC browser leg (manual — not gated)

A browser cannot open raw sockets or pick ALPN, so it is truth only for what it can speak: fetch semantics and WebSocket framing. Start the Bend servers first (see the ports below), open this file, and compare the log with the OK/DONE lines.

  1. H1: serve tests/rfc/h1_oracle.js server 19881 or bend examples/httpx/browser_leg.bend, then press Fetch.
  2. WS: serve tests/rfc/ws_oracle.js server 19884 (the same example starts both), then press WebSocket.

Two things the server must do for a browser, and both recipes do: send Access-Control-Allow-Origin on the H1 answers (this page is opened from file://, so every fetch is cross-origin) and echo the requested chat subprotocol in the 101 (a browser fails the handshake when it asked for one and the answer has none). The legs were run in a headless Chromium against the Bend example and against the oracles; the same page log ends in DONE 2/2 fetch and DONE 4/4 ws.
